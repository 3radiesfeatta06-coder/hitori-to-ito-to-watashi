# 「ログのこし」ができるまで

学長AIの会話がリロードで消えたことをきっかけに、記録用の仕組みを作り、
それを配布ツールに仕立てて、ノウハウ図書館に記事として出すまでの記録。

## はじまり

学長AIのチャットは履歴が残らない。読み返したければ、その場でスクショを撮るかコピーしておくしかない。
実際、深いところまで相談できた会話が、リロードでまるごと消えた。

最初に考えたのは「スクショを文字起こしして、あとから読み返せるようにする」こと。
ただ、消えた会話は戻らないので、**次から取りこぼさない仕組み**を先に作ることにした。

## 作ったものは2つ

| | 自分用 | 配布用 |
|---|---|---|
| 場所 | `gakucho-log/`（このリポジトリ） | `gakucho-log/app/index.html` |
| 記録の置き場所 | Markdownファイル | 使う人のブラウザの中 |
| 追加のしかた | Claude Code に貼って任せる | 画面に貼り付けて保存 |
| 想定 | 自分ひとり | リベシティの読者 |

自分用は「Claude Code がいる前提」で作れるが、配布用はそうはいかない。
インストールもログインも要らない**1ファイルのHTML**に作り直したのが「ログのこし」。

## 決めたこと

**端末をまたいだ同期はしない。**
同期するにはサーバーが要り、他人の学長AIとの会話を預かる立場になる。
運用費も障害対応も情報の管理責任も発生するし、「どこにも送信されません」という一番の安心材料が消える。
代わりに書き出し／読み込みを用意して、手で移せるようにした。

**AIの回答をお墨付きとして載せない。**
配布について学長AIに相談し、条件（個人ツールである旨の明記・利用規約の遵守）も示してもらったが、
AIの応答であって運営の許可ではない。記事では、同じ注意点を自分の判断として書いた。

**ツール名からリベシティ色を外す。**
「学長AI」を製品名に入れると商標やブランドの問題が出るうえ、他のAIでも使えるという利点が伝わらない。
「ログのこし」という一般名にして、記事の中で用途を説明する形にした。

**ぼかし機能を先に作った。**
「人に見せたいが中身は見せたくない」は自分が最初にぶつかった問題で、
結果的に「個人的なやり取りの文脈が分かる載せ方は避ける」という配慮にもそのまま応えられた。

## 途中で直したもの

- **並び順** — 日付が同じログの順序が決まっておらず、古いものが上に来ていた。`time` とファイルの更新時刻を第2・第3のキーにした
- **検索のヒット件数** — タイトルやタグの一致まで数えていて、ハイライトの数と合っていなかった。実際に光った数を数えるようにした
- **配色の差** — アクセント色しか変わらず、切り替えても違いが分からなかった。地の色から振り直した
- **文字から読み込む** — 書き出しは「文字としてコピー」ができるのに、読み込みはファイルからしかできなかった。貼り付け欄を足して、スマホ↔パソコンの移動を楽にした

## 公開まで

GitHub でリポジトリを作ろうとしたが、セッションの権限で作成できなかった。
公開URLにアカウント名が出るのも気になったため、Cloudflare Pages のダイレクトアップロードに切り替えた。

- 公開URL: https://lognokoshi.pages.dev
- 更新は同じプロジェクトで「新しいデプロイを作成」→ URLは変わらない

## 記事づくりで気をつけたこと

- 見出し画像は生成AIで作成。最初の案にライオンのキャラクターと公式風のロゴが入っていたため、
  公式ツールと誤解されないよう、キャラクターとブランド表示を外した
- 画面例には自分の実際の相談内容を使わない。当たり障りのない会話で撮るか、ぼかしをかける
- 「機種変更したとき」→「機種変更する前に」。書き出しは端末を手放す前でないと間に合わない
- リンクは冒頭と末尾の2か所に置く。最後まで読んでから使う人のために
